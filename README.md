# EDGE LAB

Платформа **paper-trading** для AI-анализа live-ставок на prediction-маркетах
(футбол, теннис; цены в стиле Polymarket, центы 0–100¢). ИИ оценивает матч,
несколько стратегий параллельно управляют **виртуальными** деньгами, и мы
сравниваем их по ROI и метрикам качества (Brier, CLV, калибровка), чтобы понять,
находит ли ИИ реальный edge против рынка.

Полное ТЗ — `docs/EDGE-LAB-техзадание.md`. Референс UI — `docs/edge-lab-v18.jsx`.

## Стек и почему так

- **Next.js 15 + TypeScript** — под будущий перенос UI из `edge-lab-v18.jsx`.
- **Node встроенный SQLite (`node:sqlite`)** — ноль зависимостей, без внешнего
  сервера БД и без нативной компиляции. Prisma сознательно **не** используется:
  её движковые бинарники (`binaries.prisma.sh`) и prebuild нативных драйверов
  (`github.com`) недоступны в заблокированных окружениях. Слой БД изолирован
  (`src/lib/db.ts`) — в проде меняется на Postgres-адаптер без правок бизнес-логики.
- Требуется Node ≥ 22.5 (флаг `--experimental-sqlite` уже прописан в scripts).

## Котировки Polymarket — что за API и как подключается (ТЗ §5.1)

**Ключ для чтения котировок НЕ нужен.** Ключ/подпись кошелька требуется только
чтобы торговать реально — здесь этого нет. Всё ниже **проверено на живом API**.

| API | База | Для чего |
|---|---|---|
| **Gamma** | `https://gamma-api.polymarket.com` | События/рынки. `/events?tag_id=<sport>&closed=false`, `/events?slug=<slug>` |
| **CLOB** | `https://clob.polymarket.com` | Цена по токену: `/midpoint?token_id=…` → `{"mid":"0.55"}`, `/price?token_id=…&side=buy\|sell`, `/book?token_id=…` |
| **WebSocket** | `wss://ws-subscribe-clob.polymarket.com/ws/market` | Реалтайм-обновления цен/стакана (вместо поллинга) |

**Модель данных (как оно есть на самом деле):**
**спортивный матч = Gamma-*событие*** с заголовком «A vs B», slug вида
`atp-alcaraz-sinner-2026-07-04` и тегом `games`. Внутри события — массив
**рынков**: победитель матча (исходы = стороны, напр. `["Alcaraz","Sinner"]`),
победители сетов, тоталы `["Over","Under"]` / `["Over 2.5",…]`, «Completed Match»
и т.д. У каждого рынка есть `outcomePrices` (снимок) и `clobTokenIds` (токены для
CLOB). Gamma отдаёт `outcomes`/`outcomePrices`/`clobTokenIds` как **JSON-строки** —
парсим `parseJsonArray()`. **Цена = вероятность:** `mid`/`outcomePrices[0]` (0…1)
× 100 = центы 0–100¢, ровно как в макете.

> ⚠️ **Ловушка тегов:** у Polymarket тег `football` (id 10) — это **американский**
> футбол. Наш «football» = soccer = tag **100350**. Tennis = tag **864**. См.
> `SPORT_TAG_IDS` в `polymarket.ts`.

### Как это встроено здесь (`src/lib/polymarket.ts`, server-only)

- `findMatchEvent({sport, home, away})` — ищет событие по тегу спорта и сверяет
  заголовок с фамилиями (скоринг 0..2). `listSportEvents()` / `fetchEventBySlug()` —
  для списка/точечной выборки.
- `eventToMarketSnapshots(event)` — превращает рынки события в строки для таблицы
  `markets` (label, цена в центах, `external_ref` = CLOB token, ликвидность).
- `getQuotes(tokens)` — реалтайм-цены с CLOB; **никогда не бросает** — каждый токен
  возвращает `Quote` с полем `source`: `live` / `snapshot` / `disabled` / `error`
  (при сбое отдаём последний snapshot и `stale:true`, ТЗ §6).
- Node `fetch` сам по себе **не** ходит через `HTTPS_PROXY` — поэтому `src/lib/http.ts`
  ставит undici `ProxyAgent`, если прокси задан (в обычном деплое — no-op).

Тянем **с сервера, а не из браузера**: обход CORS + контроль egress + graceful-фолбэк.
Официальная документация — **docs.polymarket.com** (CLOB API и Gamma Markets API).

### Проверка вживую

```bash
POLYMARKET_ENABLED=true npm run pm:probe                 # ближайший теннисный матч
npm run pm:probe -- tennis Alcaraz Sinner                # поиск по именам
npm run pm:probe -- football Португалия Хорватия
```

Проба находит событие, печатает рынки (снимок Gamma в центах) и подтягивает
реалтайм-`midpoint` по CLOB для первых рынков. Валидировано на живом API
(например, Wimbledon Juniors Doig vs Gonzalez → 16 рынков, live-котировки).
Для боевого включения живого фетча в приложении — `POLYMARKET_ENABLED=true` в `.env`.

## LLM-провайдеры (ТЗ §5.3)

Единая точка вызова `src/lib/llm.ts` (Anthropic / OpenAI / Google). Ключ берётся
из env (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_API_KEY`); отсутствие ключа
**мягко** отключает провайдера, а плохой ответ модели не роняет систему (ТЗ §6) —
вызывающий код получает `{ ok: false }` и решает сам (например, `assessment.status='failed'`).
Для порогов и генерации названий есть эвристический фолбэк, так что система
работает и без ключей. Живые вызовы к LLM-провайдерам идут через тот же
proxy-aware `http.ts`; если хост провайдера заблокирован egress-политикой или
ключа нет — вызов мягко деградирует, эвристики держат UX.

## Инварианты (ТЗ §9, проверяются в `checkInvariants`)

1. Свободный остаток казны ≥ 0 · 2. Σ долей на турнире ≤ 100% ·
3. Σ ставок стратегии на матче ≤ её бюджет · 4. ≤1 pre + ≤1 post оценки на матч ·
8. Метрики недостоверны при samples < 20 (помечаются).
Поведенческие (5,6,7,9,10) заложены архитектурой — см. комментарии в `invariants.ts`.

## UI (Этап 3)

Все 6 экранов из `edge-lab-v18.jsx` перенесены на реальные данные:

- **Сервер собирает payload** из БД (`src/lib/view.ts` → `buildAppData`), страница
  (`src/app/page.tsx`) отдаёт его в клиентский `EdgeLab` (`src/components/EdgeLab.tsx`).
- **API:** `GET /api/app` (полный payload), `POST /api/quotes` (live-котировки
  Polymarket с фолбэком), `POST /api/mutations` (единая точка записи: бюджет, доли,
  создание/правка/улучшение стратегий, аналитический промт, распознавание порогов,
  генерация названия — с проверкой инвариантов §9 на сервере).
- **Экраны:** Матчи (правая колонка котировок с кнопкой ↻ — тянет живой Polymarket),
  Лента, Портфель, Метрики (Brier/CLV/калибровка), Стратегии (промт → пороги движком,
  версии), Модели (статус ключей из env, read-only — §9.9).
- Правки бюджета/долей/стратегий **сохраняются** в БД; переполнение казны/долей
  отклоняется сервером (§9.1–9.2).

Запуск: `npm run db:seed && npm run dev` → http://localhost:3000

## Движок и спортивные данные (Этап 4)

- **Спортивный провайдер** (`src/lib/sports.ts`): `EspnSportsProvider` — публичный
  ESPN JSON API (без ключа: состояние pre/in/post, счёт, минута), `MockSportsProvider`
  для тестов/симуляции. Проверено вживую (`npm run sports:probe`). Включается
  `SPORTS_ENABLED=true`; лига — `ESPN_SOCCER_LEAGUE` (напр. `uefa.champions`).
- **Движок** (`src/lib/engine.ts`): по статусу от провайдера
  - переводит состояние матча (upcoming → live → finished);
  - триггерит переоценки на голах и движении цены, **с лимитом частоты** (§9.7:
    не чаще 1 на стратегию в N минут);
  - обновляет котировки как **версионированные snapshot’ы** (§2.10) + mark-to-market;
  - на финале: цена закрытия, **settlement** открытых ставок (§3.4) и **пересчёт
    quality_metrics** (§2.14).
  - Нарратив переоценки — от LLM с эвристическим фолбэком (работает без ключей).
- **API** `POST /api/engine`: `reassess` (кнопка «Сделать переоценку»), `refreshOdds`,
  `sync` (опрос спортивного провайдера).

Проверка вживую:
```bash
npm run simulate        # прогон матча: гол → переоценка → rate-limit → финал → settlement → метрики
npm run sports:probe -- football uefa.champions
```

## ЧМ-2026 — ядро: авто-импорт и категоризация (Этап 5)

Турниры категоризируют матчи (иерархия ТЗ §1). У турнира есть код лиги ESPN
(`competitions.external_league`), и `sync` импортирует его матчи под этот турнир:

- **ЧМ-2026 → `fifa.world`** (основной поток), **Лига чемпионов → `uefa.champions`**.
  Добавить турнир = задать его `external_league`; матчи сами раскладываются по нему.
- `POST /api/engine {action:"sync"}` (или `npm run sync:once` для cron): тянет
  scoreboard каждого связанного турнира, создаёт новые матчи под нужным турниром,
  обновляет live-счёт/состояние и (при `POLYMARKET_ENABLED`) цепляет котировки Polymarket.

Проверено вживую — `sync` импортировал реальные матчи ЧМ-2026 (Australia–Egypt,
Argentina–Cape Verde LIVE, Colombia–Ghana) под «ЧМ-2026», а PSG–Arsenal — под
«Лигой чемпионов».

## Improvement-цикл (Этап 5, ТЗ §3.5)

- `POST /api/mutations {type:"proposeImprovement", strategyId}` — **гейт samples ≥ 20**
  (иначе `gated:true` с сообщением §3.5). При достаточных данных ИИ предлагает правку
  промта (diff + обоснование); **пороги пересчитываются движком** из нового промта (§9.6).
- Приём (`improveStrategy`) создаёт **новую версию** стратегии (старая — в
  `strategy_versions`, откат/сравнение возможны). Кнопка «Улучшить по данным» на
  экране Стратегии.
- Без ключа LLM работает эвристический фолбэк, так что цикл функционирует и офлайн.
